Objective

At the end of this lab you have seen the same question answered by two designs, and you have counted the joins each one needs. You also have three questions the warehouse must answer, and Day 2 tests its star schema against them.

In this lab, the registration system and the warehouse share one database, thara, in two schemas. That is only so one portable server runs both. At the institute, the warehouse runs on its own server.

Quick check

The Dean asks whether student 3001 has a grade for Database Systems this term. What kind of question is that?

  1. A warehouse question, because the Dean asks it
  2. A look-up of one record, so an OLTP question (answer)
  3. A warehouse question, because it names a course

Why: The question finds one enrollment. A look-up of one record is an OLTP question, even when a manager asks it. A warehouse question compares terms or groups many rows.

Steps

Every step says what to run, what you should see, and what to do if you do not see it. If you do not see the expected result, stop and fix that step before you go on. Run every step in the same SQL editor.

Results are written the way psql prints them. In DBeaver, a row such as Database Systems | 9 is one row of the result grid, and an error starts with SQL Error. Getting started shows how each result looks in DBeaver.

Exercise 1: Explore the registration system

  1. Point the editor at the registration system. Open an SQL editor on the database thara in DBeaver, and run: SET search_path TO registration; You should see psql prints SET. In DBeaver, no error appears.If it fails syntax error at or near "path" means a word is missing. The setting is one word, search_path, with an underscore.

  2. Count the rows in each of the four tables.

    SELECT 'students' AS table_name, COUNT(*) AS row_count FROM students
UNION ALL SELECT 'courses', COUNT(*) FROM courses
UNION ALL SELECT 'instructors', COUNT(*) FROM instructors
UNION ALL SELECT 'enrollments', COUNT(*) FROM enrollments;

    You should see four rows: students | 24, courses | 7, instructors | 4 and enrollments | 73.If it fails relation "students" does not exist means the editor is not pointed at the registration system. Run Step 1 again in the same editor.

  3. Open the diagram of schema registration. Right-click the schema, then choose View Diagram. You should see four tables. enrollments has three lines, to students, courses and instructors.If it fails a diagram with one table and no lines means you opened a table, not the schema. Right-click registration itself.

  4. Ask the desk's kind of question. Is student 3003 enrolled in course 2002 in Semester 1 of 2024/2025?

    SELECT enrollment_id, grade
FROM enrollments
WHERE student_id = 3003 AND course_id = 2002
  AND semester = 'Semester 1' AND academic_year = '2024/2025';

    You should see one row: 5008 | A.If it fails (0 rows) means a value is typed differently from the data. The academic year is written 2024/2025, with a slash, and the semester is Semester 1.

Exercise 2: Ask the Dean's question twice

  1. Ask the Dean's question for one term. How many students enrolled in each course in Semester 1 of 2024/2025?
    SELECT c.course_name, COUNT(*) AS enrolled
FROM enrollments e
JOIN courses c ON c.course_id = e.course_id
WHERE e.semester = 'Semester 1' AND e.academic_year = '2024/2025'
GROUP BY c.course_name
ORDER BY enrolled DESC, c.course_name;
    You should see six rows, from Database Systems | 9 down to Marketing Principles | 3, and (6 rows).If it fails must appear in the GROUP BY clause means GROUP BY is missing. Every column you select beside COUNT must be named in GROUP BY.
  2. Keep the courses that had no enrollment that term. Start from courses and use a left join.
    SELECT c.course_name, COUNT(e.enrollment_id) AS enrolled
FROM courses c
LEFT JOIN enrollments e ON e.course_id = c.course_id
     AND e.semester = 'Semester 1' AND e.academic_year = '2024/2025'
GROUP BY c.course_name
ORDER BY enrolled DESC, c.course_name;
    You should see seven rows, ending with Networking Fundamentals | 0.If it fails Networking Fundamentals | 1 means you wrote COUNT(*), which counts the course row itself. Count e.enrollment_id, which is empty when no enrollment matched.
  3. Ask for the campus, which the Dean's second question needs. SELECT campus FROM students; You should see an error: ERROR: column "campus" does not exist. The registration system does not hold campus.If it fails relation "students" does not exist instead means the editor lost the schema. Run Step 1 again, then this step.
  4. Build one flat table in schema warehouse. Join every enrollment once to its student and course.
    CREATE TABLE warehouse.enrollment_flat AS
SELECT e.enrollment_id, s.first_name, s.last_name, c.course_name, c.department,
       e.semester, e.academic_year, e.grade
FROM enrollments e
JOIN students s ON s.student_id = e.student_id
JOIN courses c ON c.course_id = e.course_id;
    You should see psql prints SELECT 73, and DBeaver shows Updated Rows 73: one row for each enrollment.If it fails relation "enrollment_flat" already exists means you ran this step before. Run Step 10 to drop the table, then run this step again.
  5. Ask the Dean's question of the flat table. It needs no join.
    SELECT course_name, COUNT(*) AS enrolled
FROM warehouse.enrollment_flat
WHERE semester = 'Semester 1' AND academic_year = '2024/2025'
GROUP BY course_name
ORDER BY enrolled DESC, course_name;
    You should see the same six rows as Step 5, from Database Systems | 9, with no join.If it fails relation "enrollment_flat" does not exist means the schema name is missing. Write warehouse.enrollment_flat, because the editor points at registration.
  6. Drop the flat table, so schema warehouse is empty again for Day 2. DROP TABLE warehouse.enrollment_flat; You should see psql prints DROP TABLE. In DBeaver, no error appears.If it fails table "enrollment_flat" does not exist means it is already dropped. Go on: the Prove it check confirms the schema is empty.

Exercise 3: Turn the voices into requirements

Work on your own. Read what the Dean, the Registrar and the Head of Computing ask, in the scenario. Write three questions the warehouse must answer. For each one, name the data it needs and the shape of the answer. The shape is the columns of the answer table, such as course, term and a count. Say why the registration system cannot answer it well.

You are finished when you have one page of your own: the scenario in two sentences, then three questions. Each question names its data, the shape of its answer and why the registration system cannot answer it well. Each compares terms or groups many rows, and none is a look-up of one record.

If you are stuck, start from the Dean's question in Step 5. Ask it for every term, then by campus, and say which system holds each piece.

PROVE IT Prove it

Run these three checks in the same editor, and paste the output into your evidence.

SELECT 'students' AS table_name, COUNT(*) AS row_count FROM students
UNION ALL SELECT 'courses', COUNT(*) FROM courses
UNION ALL SELECT 'instructors', COUNT(*) FROM instructors
UNION ALL SELECT 'enrollments', COUNT(*) FROM enrollments;

You should see students | 24, courses | 7, instructors | 4, enrollments | 73.

SELECT COUNT(*) AS missing_grades
FROM enrollments
WHERE grade IS NULL
  AND NOT (semester = 'Semester 2' AND academic_year = '2024/2025');

You should see missing_grades is 4: grades nobody entered for terms that have ended. Semester 2 of 2024/2025 is still running, so the check leaves it out.

SELECT COUNT(*) AS warehouse_tables
FROM information_schema.tables
WHERE table_schema = 'warehouse';

You should see warehouse_tables is 0.

BREAK IT Break it

Try to record the same enrollment twice.

INSERT INTO enrollments VALUES (5100, 3001, 2001, 4001, 'Semester 1', '2024/2025', '2024-09-01', NULL);

You see duplicate key value violates unique constraint "enrollments_one_per_term". The error names the constraint that allows one enrollment per student, course and term. There is nothing to undo. The registration system refused the row, so duplicates can only come from outside it.
